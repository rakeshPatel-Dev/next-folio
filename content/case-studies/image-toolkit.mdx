## Project Overview

Image Toolkit is a web app that covers the full image lifecycle: convert, compress, resize, crop, and watermark.

Users upload an image, pick a tool, and every edit happens in the browser with real-time before/after previews. Batch jobs work too, and processed images can be downloaded one by one or bundled into a ZIP.

The idea came from wanting a fast, privacy-first alternative to fragmented desktop editors and server-side upload tools.

---

## The Problem

Preparing images for web, social, or print usually means juggling several disconnected tools, uploading sensitive assets to third-party servers, and waiting on slow round trips.

Most tools either process on a server, which raises privacy concerns, or they're full-featured editors with a steep learning curve for what should be simple tasks.

I wanted one upload that leads straight to a fast, secure, and simple edit-and-download flow.

---

## Goals

- Let users pick a tool and start editing immediately.
- Process everything client-side for privacy and speed.
- Cover the common jobs: convert, compress, resize, crop, watermark.
- Handle multiple images at once with ZIP batch downloads.
- Keep the flow minimal: upload, edit, download.

## The Solution

The app walks the user from an upload to a downloadable result through dedicated tool pages.

Upload an image, pick a tool (Convert, Compress, Resize, Crop, or Watermark), adjust the settings, preview the result in real time, then download it on its own or as part of a batch ZIP.

## Key Features

### Image Conversion

Converts between JPG, PNG, WebP, GIF, and BMP with quality control and batch processing.

### Compression

Reduces file sizes with a preview comparison and target-size controls.

### Resize

Changes dimensions with preset sizes (YouTube, Instagram, Web) and aspect-ratio locking.

### Cropping

Custom aspect ratios (1:1, 4:3, 16:9) with a drag-to-resize selection.

### Watermarking

Adds text or image watermarks with position, rotation, opacity, and blend modes.

### Batch Processing

Handles multiple images at once and downloads them all as a ZIP.

## Key Technical Decisions

### Browser as the Processing Engine

The Canvas API handles all manipulation locally, so images never leave the user's device. That removes both privacy concerns and upload latency in one move.

### One Tool Per Page

Each task gets its own focused route (Convert, Compress, Resize, Crop, Watermark) instead of one overwhelming editor.

### Real-time Preview

Every tool renders a before/after comparison, so users see the result of their settings instantly.

### ZIP for Batch Downloads

JSZip bundles multiple processed images into a single download, which keeps the batch flow simple.

---

## Challenges & Solutions

### Performance on Large Images

Canvas operations on large files can get slow in the browser.

**Solution:** Compression uses browser-image-compression for smarter size reduction, and previews update in real time so users see results without waiting.

### Keeping Crop UX Intuitive

Custom aspect ratios and drag-to-resize selections are easy to get wrong.

**Solution:** react-easy-crop provides a well-tested drag-and-resize cropping interface.

### Consistent UX Across Tools

Five tools with different controls risk feeling disconnected from each other.

**Solution:** Shared animated UI components and the same upload, edit, download layout across every tool page.

### No Server to Leak or Store Data

The privacy promise depends on the client doing everything.

**Solution:** All processing happens client-side by design, with no backend and no data collection.

<Callout variant="warning" title="Privacy is the product">
  Because there's no server, there's also no backend to audit. That's both the
  feature and the constraint: any future account or AI features have to keep
  this client-side promise intact.
</Callout>

## Security & Performance

### Security

- No server storage. Images are processed entirely in the browser.
- No data collection. Images are never stored, analyzed, or tracked.
- HTTPS-only data transmission.

### Performance

- Client-side processing removes upload and round-trip latency.
- Batch jobs use JSZip to bundle results into a single download.
- Responsive, mobile-first design keeps interactions snappy.

## Lessons Learned

### A single clear flow beats many options

Keeping the core journey to upload, edit, download made every tool immediately understandable.

### Client-side processing is a strong differentiator

Doing everything in the browser removes privacy objections and latency in a single decision.

### Focused tools beat one big editor

Dedicated pages for each task keep the learning curve low and the interface simple.

### Batch support turns a utility into a workflow

ZIP downloads and multi-image handling made the tool practical for real workloads.
