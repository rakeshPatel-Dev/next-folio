## Project Overview

isHirable is a web app that uses GitHub data and AI to help understand a developer's technical background.

It looks at things like repositories, commits, pull requests, and programming languages, then presents that data through visual summaries and AI-generated insights.

The idea came from wondering whether a developer's actual work on GitHub could give more useful context than a resume's list of skills.

---

## The Problem

A developer's skill set can be hard to read from a resume or a list of technologies alone.

GitHub already holds a lot of useful signal about what developers have worked on, but manually digging through repositories, activity, and languages takes time.

I wanted a tool that collects that information and shows it in a simpler way.

---

## Goals

- Analyze publicly available GitHub developer data.
- Show development activity in a format that's easy to skim.
- Provide useful summaries of repositories and technologies.
- Experiment with using AI to interpret technical data.
- Build a practical AI-powered product instead of just another chatbot.

## The Solution

The app takes a GitHub profile and collects the relevant development information.

That data is then processed and shown across different sections of the developer profile, including repository info, language usage, and activity.

AI is layered on top to generate additional insights from what's already been collected.

## Key Technical Decisions

### Using GitHub as the Primary Data Source

GitHub shows actual development activity rather than only self-reported skills.

For this project, it was a good place to experiment with developer analysis.

### Using AI for Interpretation

Instead of making AI the main interface, I used it to interpret information that had already been collected.

That keeps the AI feature tied to real developer data.

### Visualizing GitHub Data

Raw API responses are hard to read quickly, so important pieces like language usage and activity were turned into visual components.

---

## Challenges & Solutions

### Working With GitHub API Data

GitHub returns a lot of information, and most of it isn't useful for the final interface.

**Solution:** I picked the data points that mattered most for the developer profile and shaped them before displaying anything.

### Making Technical Data Understandable

Commit counts, repository info, and language stats aren't very useful when you just dump the raw numbers on screen.

**Solution:** Charts, summaries, and grouped information made the data easier to scan.

### Integrating AI With Structured Data

Sending a big pile of GitHub information straight to an AI model tends to produce poor or off-topic answers.

**Solution:** I prepared the relevant developer information first, then passed only what the model needed.

## Security & Performance

### Security

- API keys and secrets stay out of the client-side app.
- GitHub data is accessed through the appropriate API endpoints.
- Only the data the app actually needs gets processed.

### Performance

The app avoids unnecessary API and AI requests wherever it can.

GitHub API usage also has to be handled carefully because of rate limits.

## Lessons Learned

### AI quality depends heavily on the input

A better model doesn't automatically produce better results. The quality and structure of the information you feed it matter more than the model itself.

### APIs need to be designed around the product

GitHub gives back much more data than the app needs. Figuring out what to pull, process, and show was a big part of the work.

### Data visualization improves usability

Showing technical information visually made the profile easier to understand than raw statistics ever would.

---

## What I'd Improve

If I kept building isHirable, I'd focus on:

- Improving the accuracy of AI-generated insights.
- Adding better filtering and search.
- Improving how developers are compared against specific requirements.
- Adding more detailed repository analysis.
- Improving handling of GitHub API rate limits.
- Making AI-generated conclusions easier to verify against the underlying data.
